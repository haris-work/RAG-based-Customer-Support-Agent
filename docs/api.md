## Customer chat

**Request:** `POST /api/chat` with JSON payload:

```json
{"message":"What is your return policy?","conversation_id":null}
```

The customer browser uses the `novatech_session` HttpOnly cookie, established when the API creates a session. Origin/custom-header checks are planned after Step 5.20. Never send the cookie value in documentation or logs.

**Representative response** (illustrative, not generated by an actual request):

```json
{
  "conversation_id": "79bd67d4-9784-4d2e-a73c-92dd2f028eb2",
  "answer": "Please consult the relevant policy for eligibility.",
  "intent": "policy_inquiry",
  "status": "answered",
  "sources": [],
  "ticket_id": null
}
```

Only the conversation owner can resume a previous `conversation_id`. Expect 401 for missing/expired session credentials, 403 for another session's conversation, and 422 for invalid input. HTTP 429 rate limiting is planned for Step 5.25. Server or retrieval errors may return 503.

## Administrator authentication

Send `X-Admin-Key: <your-private-admin-key>` on ticket, analytics and notification API requests. The shared key does not identify individual employees. Do not expose it in screenshots, client code or public documentation.

### Ticket transitions

`PATCH /api/tickets/{ticket_id}/status` JSON:

```json
{"status":"in_progress"}
```

The service enforces valid status transitions and writes a corresponding audit event when a transition changes state. Invalid transitions return an error rather than silently changing the ticket.

### Audit history

`GET /api/tickets/{ticket_id}/history` returns the ticket ID, total audit events and ordered event records including previous status, new status, actor and timestamp.

## Analytics

`GET /api/analytics/overview` reports total, pending, in-progress, resolved and open tickets, resolution rate, average resolution hours, sample size and counts by intent.

Date-range filtering uses ISO calendar dates and is inclusive by **ticket creation date (UTC)**:

`GET /api/analytics/report?start_date=2026-11-01&end_date=2026-11-25`

`GET /api/analytics/export?start_date=2026-11-01&end_date=2026-11-25` returns CSV without raw customer message text. Metrics reflect current ticket statuses for tickets created in the requested period, not historical end-of-period snapshots.

## Notification monitoring

Notification attempt history and retry services exist in the core implementation. Dedicated notification-monitoring and manual recovery endpoints are planned for Step 5.24, not assumed complete at Step 5.20.
